# 01 · 问题从哪来

## 原始疑惑（用户原意转写）

有没有一个词（中英皆可），用来形容：

> **很少几个词一出现，对话双方就能自动对齐「我们在谈哪个领域、哪套框架」。**

例子：

- 说到 `header` / `body`，即便没说「我要做 API」，人也知道在 HTTP 请求语境里。
- 说到「反代」，在特定圈子里会联想到大模型网关、token、上游转发等链路。

进一步目标不只是「知道这个现象叫什么」，而是：

1. **A**：一说这些词，对方立刻懂你在哪个领域  
2. **C**：拿**总称**去问 AI：「给我这个领域的这类词」，快速建图  
3. **B**（次要）：能跟资深者有共同语言（架构、延迟、QPS…）

一长串术语清单也算，不只是两三个词。

「锚点」感觉沾边，但不像那个可检索、可写进 prompt 的正式总称。接近的候选包括 shibboleth、seed terms、core lexicon 等。

## 要解决的具体痛点

| 痛点 | 表现 |
|---|---|
| 叫不出名字 | 知道想要什么，只能用白话形容，AI 反复猜 |
| 学新领域慢 | 没有高密度词表，读材料抓不住骨架 |
| prompt 不稳 | 同需求每次说法不同，模型飘到邻域 |
| 难变 skill | 方法停在聊天里，无法回流成可复用教学流程 |

## 对话中如何被钉准

多轮澄清后的共识：

- 要的是 **入口词 + 骨架词** 合集，不是单纯装逼黑话。  
- 关键用法是 **双重方向**：  
  - **反向**：用总称让 AI 吐出领域词表  
  - **正向**：拿词表去要解释、对比、方案、代码  
- 没有单一官方名，而是 **一簇近亲**；对外可统称 Vocabulary-First / Glossary-First。

## 本仓库要沉淀什么

- 疑惑本身（避免以后忘了「我到底在找什么」）  
- 词表家族与各自侧重点  
- 可复制 prompt  
- 网上同思路证据与链接  
- 可交给其他 AI 写成 skill 的种子
